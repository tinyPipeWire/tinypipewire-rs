# tinypipewire-rs

Rust bindings to [tinypipewire], a small C library that wraps PipeWire's
`pw_stream` for audio and video capture, audio playback, and multi-port
filters.

| Crate | What it is |
| --- | --- |
| [`tinypipewire-sys`](tinypipewire-sys) | Raw FFI declarations, generated from the C headers by bindgen |
| [`tinypipewire`](tinypipewire) | The safe interface: owned handles, `Result`, and Rust closures for the C callbacks |

The bindings track C API 0.8.0, pinned as a submodule under `vendor/`.

## Requirements

PipeWire is Linux-only, so the crates build and run there. Building needs
`libpipewire-0.3` >= 0.3.50 development files, and either `tinypipewire`
>= 0.8.0 installed or the Meson toolchain to build the vendored copy.

An older installed `tinypipewire` is not an error. pkg-config passes over it
and the build falls back to the vendored sources, saying so in a warning, so
check that warning if the library you meant to link against went unused.

```sh
sudo apt-get install meson ninja-build pkg-config libpipewire-0.3-dev libspa-0.2-dev
git clone --recurse-submodules https://github.com/tinyPipeWire/tinypipewire-rs
cargo build --features vendored
```

## Using it

```toml
[dependencies]
tinypipewire = "0.8"
```

Capture from the default microphone for five seconds:

```rust
use tinypipewire::{AudioConfig, Stream, StreamType};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let stream = Stream::new_capture(StreamType::Audio, |buf| {
        if let Some(data) = buf.data() {
            println!("{} bytes (pts={:?} ns)", data.len(), buf.pts());
        }
    })?;

    stream.set_audio_config(&AudioConfig::new(48_000, 2))?;
    stream.start()?;
    std::thread::sleep(std::time::Duration::from_secs(5));
    stream.stop(false)?;
    Ok(())
}
```

Every callback runs on the PipeWire thread loop the handle owns, so each
closure is `Send + 'static`, and the buffers it receives borrow the graph's
memory for one call only. Dropping a `Stream` or `Filter` stops it and joins
that thread.

## Examples

Each runs with `cargo run --example <name>`:

| Example | What it shows |
| --- | --- |
| `audio_capture` | Capture from the default audio source, stopping when the source is lost |
| `video_capture` | Capture 640x480 YUYV from the default camera |
| `audio_playback` | Play a 440 Hz tone to the default sink, or to one named on the command line |
| `list_targets` | Print every target a stream would accept, with each camera's formats |
| `filter_mix` | Mix two audio input ports into one audio output port |

## How the C library is found

`tinypipewire-sys` probes `pkg-config` for an installed `tinypipewire` first.
When that fails, or when the `vendored` feature is on, it builds the pinned
sources under `vendor/tinypipewire` with Meson and links them statically;
PipeWire itself still comes from the system either way.

Bindings are generated by bindgen at build time. Turning the default `bindgen`
feature off uses the copy committed at
`tinypipewire-sys/src/bindings/pregenerated.rs` instead, which is also what
docs.rs builds against. To refresh that copy after a C API change:

```sh
TINYPIPEWIRE_SYS_UPDATE_BINDINGS=1 cargo build -p tinypipewire-sys
```

On a machine with no PipeWire — macOS, say — the same works against the
submodule's own headers, which skips linking entirely:

```sh
TINYPIPEWIRE_SYS_HEADERS_ONLY=1 TINYPIPEWIRE_SYS_UPDATE_BINDINGS=1 \
  cargo build -p tinypipewire-sys
```

Set that variable to a directory instead of `1` to read some other install's
headers. Either way the crate compiles but cannot be linked, so it is for
`cargo check` and for refreshing the committed bindings.
